# 从简历抽取事实的注意事项

## 读文件

- 先试 PDF 文本层；文本层是空的（扫描件、图片型 PDF）就改用 OCR，或用视觉能力逐页读。
- Word 文档（`.docx`）优先读正文段落与表格；表格里的内容常被排版成"字段 | 值"两列。
- 没有文本层又没有 OCR 或视觉能力时，直接请用户提供可复制的文本，不要凭页面的模糊印象硬猜。
- 页眉页脚、页码、水印不是事实来源，不要当成属性值。

## 排版陷阱

- **多列排版**：PDF 抽出来的文本可能把两栏内容交错在一起。判断依据是语义，不是行号。拿不准就整段贴给用户确认。
- **Tab 顺序错乱**：时间、公司、岗位常被抽成上下三行，需要按语义重新配对。
- **日期格式混杂**：`2024.9 – 至今`、`2016.9-2020.6`、`2026年8月15日-2026年9月15日` 都可能出现。落库时统一写规范格式，但**不要替用户补全**没有写出来的日或月——不确定就按原文粒度写，并记进提问清单。
- **连接符**：PDF 里常用 U+2010 等排版连字符，落库时统一成半角 `-`；专有名词里的连字符保留原文写法。
- **括号与别名**：同一实体在不同地方写法不同（简称、全称、英文名）。全称、简称分别有对应属性时，两个都落；只有一个属性时按该属性的说明选一个，另一个记进 `## 备注`。

## 归属判断

- **不要按简历的栏目名机械映射**。简历上"实习、工作经历"一栏常常同时装着实习和全职，要按时间跨度、是否在校期间、职位性质拆到 `实习经历` 与 `全职工作经历`。
- 同一件事可能同时够格进两个类（例如在校期间做的横向项目）。按类 README 的 `## 填法说明` 判定主归属，只在另一类里留一句概括，不要两处写全文。
- 学历、学位、成绩类信息挂到对应那一段经历上，不要全塞进 `个人信息`。
- 荣誉与奖项里的"证书"分两种：奖项本身进 `获奖情况`，技能类证书（等级考试、语言考试）进 `技能` 或 `外语能力`。

## 缺口判定

对每个拿不到值的属性，先分清是哪种情况：

- **结构上不适用**（例如尚未毕业的学历段没有毕业证书）→ 标 `〔不适用〕` 并写明原因。
- **简历没写、但用户可能知道**（例如证件有效期、证明人联系方式、附件文件）→ 标 `待补`，进提问清单。
- **简历写得含糊**（例如"若干次获奖"没写具体名称与时间）→ 标 `待补`，把原文一并给用户看，请他补全或确认要不要拆成多条实例。

不要为了让检查通过而把 `待补` 写成 `〔不适用〕`，也不要"合理推测"一个值。

## 多份简历

- 中文、英文两份，或新旧两版，都要合并进同一个简历文件夹。
- 英文简历里的信息要按中文类的口径落库；专有名词保留原文，必要时在 `## 备注` 里写中文对照。
- 同一属性在几份简历里取值不同时，不要自行取舍，列进提问清单（给出各版本的值和出处），由用户裁决。

## 实例粒度

- 一个实体一个实例：一段学历、一段实习、一段全职、一项奖励、一个项目、一位家庭成员各一个文件。
- 同一实体的多段经历不要合并成一个文件；同名实体的多份（例如两次同名奖学金）用年份或序号区分文件名。
- 同一项目下的多次贡献写在同一个文件里，用子表或正文分条列出。
