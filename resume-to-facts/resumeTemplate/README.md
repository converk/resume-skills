# resumeTemplate

本目录是一份简历文件夹的**模板**：把简历里的信息拆成稳定的结构，供填写招聘表单、生成简历、准备面试等场景取用。事实只维护一份，其他场合从中读取，不各自复制。

用法：把本目录整体复制到**工作区**（不要在技能包目录里就地改），目录名用默认的 `generated-resume`（即 `<工作区根目录>/generated-resume`），再按每个类的 `模板.md` 逐条填值，形成实例文件。**复制出来的是数据，本目录里不放任何个人信息。**

## 结构

- 一个子目录 = 一个类，目录名就是类名。
- 类目录里固定两个文件：
  - `README.md`——这一类记什么、实例怎么命名切分、注意事项与降级策略、没有对应栏目时填到哪里。
  - `模板.md`——属性规范，一行一条属性：属性名、形态、必填性（含条件）、取值枚举、说明。
- 类目录里的其余 `.md` 是实例文件，一个实例一个文件；附件文件（证件照、成绩单、证书扫描件、证明等）与实例放在同一个目录里。
- 根目录的 `README.md`（本文件）是库级契约。

## 属性值的三种状态

- `- 属性：值` —— 已知。
- `- 属性：〔不适用〕原因` —— 这一类实例天然没有这个属性，括号内写明原因。
- `- 属性：待补（缺什么）` —— 还没有值，需要补。

简历文件夹里出现「待补」就说明这份库还没完工。

## 必填与可空缺

每个类的 `模板.md` 会标出这个属性是「必填」还是「可空缺」：

- **必填**：这条属性必须有个交代——要么是值，要么是 `〔不适用〕原因`。
- **可空缺**：这个属性可以整行不出现，表示"没有这一项"。
- 带条件的写法是 `必填（<实例条件>可空缺）`：默认必填，但满足条件的那些实例可以没有。

## 已确认没有的项

有些"没有"是问过、用户确实没有，而不是漏了。这类结论集中记在这一节下面，一行一条，格式是 `<类名>：<确认了什么没有>`：整个类没有实例可以记在这里，某一类里缺少某个必备实例也可以记在这里。一个库一处，不另建文件。

只写用户明确确认过的结论。某个类目录里既没有实例、这里也没有记录，就说明这一类还没问过。

## 附件

附件属性的值是路径，统一写成相对工作区根目录的路径，不要写绝对路径。

## 类清单

个人信息、教育经历、实习经历、全职工作经历、外语能力、技能、获奖情况、家庭成员情况、校内活动和社会实践、项目经验、开源贡献、科研经历、主观题。

没有实例的类目录可以保留也可以删掉；保留便于以后补充。

## 改动纪律

- 不写没有来源的信息。拿不准的值标 `待补`，不要写一个"看起来合理"的值。
- 改 `模板.md` 里的属性或必填性之前，先确认在用的实例会不会因此变成缺项。
