# 开源贡献

一个文件代表一个开源项目上的贡献；同一项目下的多次贡献写在同一个文件里。

## 实例

- 文件名：`<项目名称>.md`。

## 注意事项与降级

- 属性清单见同目录的 `模板.md`。
- `项目规模` 写能说明项目量级的客观数字，并写清数字的口径与时间点。
- `贡献形式` 写 Pull Request、插件开发、文档、Issue 排查等；一种形式一条，多次同类贡献合并写清次数。
- `贡献内容` 写做了什么；具体改了哪些文件、修了哪些 bug 属于可补充的细节，拿不到就先写概要。
- `成果` 写是否被合并、被采纳、带来什么可量化变化；没有明确结果的如实写"已提交"。
- 项目名称、地址如果简历里只给了简称，要核对准确写法后再落库；核对不了就标 `待补`。

## 填写位置

招聘网站通常没有"开源贡献"栏目，按下面的优先级放置：

1. 有"项目经历/项目经验"栏时，按项目经历的格式填入，并注明这是开源贡献；
2. 没有项目经历栏时，填进"校内活动和社会实践"这类栏目；
3. 连这类栏目也没有时，压缩成一句话放进自我评价或"其他补充信息"。
