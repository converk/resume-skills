# 项目经验

一个文件代表一个项目。

## 实例

- 文件名：`<项目名称>.md`，可用简称。
- 同一项目的不同阶段算一个文件，不要按里程碑拆成多个。

## 注意事项与降级

- 属性清单见同目录的 `模板.md`。
- 描述按字数分档维护，是为了适配不同网站的字数限制。填写时优先用不超过限制的最完整版本；完整性优先级从高到低，不要为了短而丢关键结果。
- 每一档都是可独立使用的一段完整表述，不是上一档的截断。短档只保留最核心的做法与结果。
- `担任职务` 写在这个项目里承担的角色与职责，不是公司里的岗位名。
- `所在单位` 填项目归属的组织；在校项目写学校，工作项目写公司或部门。
- `项目地址` 用于开源项目或有公开主页的项目；没有就写「无」。
- 项目在简历里可能只占一行。这种情况先按这一行落库，再把缺的细节列进提问清单，不要用简历里其他段落的内容拼凑。

## 填写位置

招聘网站没有"项目经历/项目经验"这类栏目时，把本类实例填进"校内活动和社会实践"，四个必填项一一对应：

| 项目经验 | 校内活动和社会实践 |
| --- | --- |
| 所在单位 | 社团或组织名称 |
| 担任职务 | 职务 |
| 项目时间 | 活动起止时间 |
| 项目描述（按字数限制选档） | 工作描述 |

- 描述按目标栏目的字数限制取对应档位（完整 / 500 / 300 / 200 字），措辞按校内活动的口径写。
- 在工作单位做的项目填进去时，`社团或组织名称` 照实写公司或部门，不要让读者误以为是在校项目。
