# 简历文件夹结构契约

本文件是简历文件夹的结构契约：负责建库的 skill 按它生成，负责填表的 skill 按它读取。两个 skill 各有一份同名副本，改动结构时两份要一起改。

## 目录布局

```
<工作区>/generated-resume/
├── README.md                   # 根说明：结构、三态、附件路径、类清单、已确认没有的项
├── <类名>/                      # 一个类一个目录；附件文件与实例同级
│   ├── README.md               # 类说明：这一类记什么、实例怎么命名、注意事项与降级、填写位置
│   ├── 模板.md                  # 类契约：属性规范，一行一条
│   └── <实例>.md                # 实例数据
└── ...
```

类目录名就是类名（中文）。一个类可以有任意多个实例文件，也可以一个实例都没有。

产出目录里只该有：根 `README.md`、类 `README.md`、类 `模板.md`、实例文件和附件。不要留骨架、缺口清单这类中间文件。

## 类目录契约

每个类目录固定两个文件，职责不重叠：

- `README.md`——**类说明**：这一类记什么、实例怎么命名与切分、注意事项与降级策略、没有对应栏目时改填到哪里。
- `模板.md`——**属性规范**：这一类有哪些属性、每个属性算不算必填、取值有哪些。

`README.md` 固定包含下面几节，顺序一致：

```markdown
# <类名>

<一句话：一个文件代表什么>

## 实例

- 文件名格式与主键规则；同名或同实体多份时怎么区分

## 必备实例

- <关键词>：<什么场景下必须存在，没有时必须向用户确认>   （只有需要时才写这一节）

## 注意事项与降级

- 什么值能从常见来源拿到、什么值拿不到、缺失时降级到哪、什么情况下应当标「不适用」

## 填写位置        （可选，只有需要时才写）

- 目标网站没有对应栏目时，这一类的内容应当改填到哪里
```

`模板.md` 里是一张属性表，语法见下节。

## 模板.md 的属性表语法

`模板.md` 只有一个标题加一张表，**一行一条属性**，列固定为这五列：

| 列 | 含义 |
| --- | --- |
| 属性 | 属性名 |
| 形态 | `单值`、`正文`、`子表`、`附件` 四者之一 |
| 必填性 | `必填`、`可空缺`，或带条件的 `必填（<实例条件>可空缺）` |
| 取值 | 受限制时写候选值与枚举，用 `/` 分隔；没有限制写 `—` |
| 说明 | 一句话讲清这条属性写什么、拿不到时怎么办 |

规则：

- **形态**：`单值` 在实例里写成 `- 属性：值`；`正文` 写成同名 `## 属性名` 段落，实例里必须非空；`子表` 写成 `### <子表名>…` 段落；`附件` 的值是文件路径。
- **必填性只有两个基准值**：`必填`、`可空缺`。**每个属性都必须显式写一个**，因为下面要逐项审查。
  - `必填` = 这条属性必须有个交代：要么是值，要么是 `〔不适用〕原因`；只允许在没完工时暂时是 `待补`。
  - `可空缺` = 这个属性可以整行不出现（即"没有这个属性"），出现时按同样规则校验。
- **带条件**的写法是 `必填（<实例条件>可空缺）`，含义是"默认必填，但在这些实例上可以空缺"。执行上它比 `可空缺` 严一档：不适用的实例要写 `〔不适用〕原因`，不要整行省掉。
- **取值**列只是给填写方看的候选值，不参与必填判断。枚举用 `/` 分隔，如 `国家级/省级/校级/院系级`。
- 子表只支持一层，子属性写成 `父属性 · 子属性`（如 `证书 · 名称`），不要出现更深的层级。
- 属性名可以带括号限定口径（如 `关系（表格口径）`），这时整串都是属性名。

## 必备实例

有些"这一类至少得有哪几个实例"是常识，但简历里往往不写，抽完就静默缺了。这类要求写在类 README 的 `## 必备实例` 里：

```markdown
## 必备实例

- 高中：应届生、在读生与校招场景必备。多数校招系统的教育经历要求从高中填起，而简历通常不写高中，所以没有时必须向用户确认。
```

- 每一行是 `- <检索关键词>：<什么场景必备、没有时怎么办>`。
- 检索关键词会在该类所有实例文件的全文里搜索；搜不到就报「必备实例待确认」。
- `## 必备实例` 是**场景相关**的：关键词不代表无条件必备，条件写清楚，由 agent 向用户确认。

## 已确认没有的项

有些"没有"是问过、用户确实没有，而不是漏了。这类结论集中记在**简历文件夹的根 `README.md` 的「已确认没有的项」小节**里——一个库一处，不另建文件：

```markdown
## 已确认没有的项

- 校内活动和社会实践：用户确认没有校内任职与社会实践经历
- 教育经历 · 高中段：用户确认不提供（走社招，不用从高中填起）
- 个人信息 · 生活照：用户确认不提供
```

- 每一个类都要有交代：**要么有实例文件，要么在这里记过"用户确认没有"**。两者都没有视为"未交代"，自检时算缺口。
- 只记用户明确确认过的结论，不记推测。

## 实例文件契约

```markdown
# <类名> · <实例名>

## 属性

- 姓名：张三
- 证件照：generated-resume/个人信息/证件照.jpg

### 证书：CET4

- 名称：CET4
- 分数：459

### 证书：CET6

- 名称：CET6
- 分数：428

## 工作描述

- 负责某某系统日常开发
- 参与某某架构迭代

## 备注

- 不参与校验，可以写口径说明、来源说明、待确认事项
```

规则：

- 第一行标题固定为 `# <类名> · <实例名>`，中间的间隔符是 ` · `。
- 顶层属性写在 `## 属性` 段里，形式为 `- 键：值`（冒号全角半角都可以，取第一个冒号切分）。
- 子表用 `### <子表名>` 或 `### <子表名>：<条目名>`；`## 属性` 段一直延伸到下一个 `## ` 标题，所以 `###` 段落都在其中。
- 正文类属性用同名标题 `## <属性名>`，内容可以是条目列表或段落。
- `## 备注` 不参与校验，也不要在这里放本该进属性的值。
- 一个实例文件的属性集合必须覆盖该类 `模板.md` 里的全部属性，一条都不能少。

## 三态值

每个属性的值必须是三态之一：

| 状态 | 写法 | 含义 |
| --- | --- | --- |
| 已知 | `- 属性：值` | 有确定值 |
| 不适用 | `- 属性：〔不适用〕原因` | 结构上不适用，原因必填 |
| 待补 | `- 属性：待补（缺什么）` | 还没有值，需要在提问清单里继续追 |

判定方式：值以 `待补` 开头即为待补；值中含 `〔不适用〕` 即为不适用；其余视为已知。

收工条件是**所有实例的缺项为 0、待补为 0**。不适用不算缺口。

注意：**「待补」只是运行中的中间态**，不写进类 `模板.md`。`模板.md` 只回答这个属性是「必填」还是「可空缺」，值层面的三态由实例文件承担。

## 附件属性

- 附件属性的值是路径，不写文件内容。
- 约定写法是**相对工作区根目录的路径**，例如 `generated-resume/个人信息/证件照.jpg`。
- 校验时会按上面的规则解析路径并检查文件是否存在。

## 简历文件夹在哪里

结构固定，不做搜索：

- **简历文件夹**：工作区根目录下的 `generated-resume/`。工作区根目录就是当前工作目录；用户明确指定了别处时按用户的来。
- **模板目录**：`resume-to-facts/resumeTemplate/`（建库时整份复制，就成了简历文件夹；只填表时用不到它）。
- **附件路径**：按工作区根目录解析，例如 `generated-resume/个人信息/证件照.jpg`。

简历文件夹不存在或为空时，把模板目录整体复制过去再开始填值。

## 收工前的核对

这套规范不配校验脚本：**是否完工由模型判断**。分两轮，两轮都过才算收工。

**第一轮：机械项**——逐类逐实例对着下面的清单过（用什么手段读文件都行，判断由模型做）：

1. 每个类目录都有 `README.md` 与 `模板.md`，且 `模板.md` 里有属性表。
2. 该类有实例文件，或简历文件夹的根 `README.md` 的「已确认没有的项」里记过"用户确认没有"；`## 必备实例` 列出的每一项都有实例或已确认记录。
3. 该类 `模板.md` 标为 `必填` 的每个属性，在每个实例里都有交代；形态为 `正文` 的属性有同名段落且非空；形态为 `子表` 的属性至少有一个 `### 名称…` 段落，段内必填子属性一个不少。
4. 全库没有任何 `待补`（属性行与正文段都算）。
5. 每个附件属性指向的文件在磁盘上存在，路径按「附件属性」一节的规则解析。
6. 带条件的属性逐实例过一遍：适用的实例要有值，不适用的实例要有 `〔不适用〕原因`。
7. 产出目录里没有多余的中间文件（骨架、缺口清单之类）；类目录里只该有 `README.md`、`模板.md`、实例文件与附件。

**第二轮：语义项**——只能靠模型看用户数据的部分：

- 可空缺的属性，在这个用户的实际情况下是不是本该有值（例如简历里有六级成绩，`外语能力/` 的证书子表就不该空着）；
- 有没有整段经历被漏抽、有没有值填得和简历不符；
- 附件文件名与实际内容对不对得上。

输出怎么交给用户、格式什么样，见 `resume-to-facts` 的 `SKILL.md`「自检扫描」与「缺项清单与报告」两节。

## 扩展新类

1. 在模板目录（默认 `resumeTemplate/`）下按上面格式新建类目录，写 `README.md`（类说明）与 `模板.md`（属性表）。
2. 在简历文件夹的根 `README.md` 的类清单里加一行。
