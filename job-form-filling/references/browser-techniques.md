# 浏览器自动化实现技巧

`SKILL.md` 里是工具无关的现象与对策，本文件放具体实现细节。

标注约定：

- **【通用】** 换任何通道都成立的操作原则，到具体页面上再核对一遍。
- **【通道相关】** 只对某一类自动化通道成立，换通道要重新验证。

## 一、通道选择

- 【通用】优先使用内置浏览器（宿主应用自带的浏览器，例如 Codex 桌面版应用内的浏览器），而不是用户自己开着的 Chrome / Edge：它与环境隔离，不会和用户抢同一份简历编辑会话，可控性也更好。改用外部浏览器时要在报告里说明。
- 【通用】先探测当前环境有哪些可用通道，选一个既能读值、又能写值、还能真正触发页面框架状态的通道，然后全程只用它，不要在任务中途换。
- 【通用】优先选登录态能跨回合保持的通道（独立 profile、持久化上下文）。每次都要重新登录的通道，在需要短信验证码的站点上会反复打断流程。
- 【通用】没有浏览器能力时不要硬凑：直接降级成"生成填写清单交给用户手工填"。
- 【通道相关】有的系统级桌面自动化通道读不到浏览器窗口状态（会被安全策略中止，拿不到当前 URL），不适合做表单填写。
- 【通道相关】有的浏览器扩展通道拿不到宿主机凭据，会直接报未授权。遇到就换通道。
- 【通道相关】有的通道会在回合之间回收标签页，需要在每轮结束前调用它的保活或交接接口，否则下一回合页面消失。接口名按当前通道的文档来。

## 二、读值

- 【通用】读值不能只看页面显示，要读控件真实的值。
- 【通道相关】某些封装层的求值接口读 `.value` 会拿到旧值——明明写进去了也读成空。这时直接走底层求值接口（例如 CDP 的 `Runtime.evaluate`）。
- 【通用】保存到底有没有落到服务器，以成功提示或保存接口的返回码为判据。不要靠刷新页面核对：刷新会让没保存的内容直接丢，见「八、标签页生命周期」。

## 三、写值

- 【通用】用真实鼠标点击加真实键盘输入：点中控件 → 全选 → 删除 → 输入文本 → （必要时回车）。
- 【通用】不要用"设置 value 再派发 `input`/`change`"代替真实输入。在一些前端框架渲染的站点上，页面显示是对的，但框架状态没更新，点保存会报"某字段未填写"。判据就是**显示有值但校验不过**。
- 【通道相关】点击用真实鼠标事件（例如 CDP 的 `Input.dispatchMouseEvent`），不要只调元素的 `.click()`；下拉弹层里的候选项常只认真实鼠标事件。
- 【通用】输入中文用"直接输入文本"的接口，不要逐键模拟按键，避免输入法状态干扰。

## 四、控件

- 【通用】**下拉**：点开弹层，再点候选项。只改 `select` 的值在框架站点上不可靠。
- 【通用】**联动下拉**（省/市、门类/专业）：先选父级，等子级选项加载完再选子级。父级没选时子级常显示"暂无数据"。
- 【通用】**可搜索下拉**（学校、专业）：点开 → 输入关键词 → 等列表出现 → **先取一次候选列表文本核对** → 点中完全匹配的那一项。列表里通常还有"使用「XXX」作为我的学校/专业"这类自定义项，按用户的实际选择决定用不用。
- 【通用】候选列表会随输入变化，每次点之前重新取候选文本，不要复用上一次的坐标。
- 【通用】**日期控件**多为只读：先移除只读属性，再用键盘输入 `YYYY-MM-DD`，回车，最后读值确认。
- 【通用】**年月拆分**：有的站点把年月做成两个 `select`、真值放在隐藏 `input` 里，两个都要写。
- 【通用】**复选框/单选框**：点它的 label 或控件本身，不要只改 `checked`。

## 五、定位元素

- 【通用】优先用稳定的业务标识（`name`、`id`、label 文本），不要用位置索引和绝对路径选择器。
- 【通用】有的站点把字段 `id` 拼成"区块-字段-条目序号"这样一串用下划线连接的标识，可据此精确定位。
- 【通用】`id` 以数字开头时不能写 `#123_456_0`（CSS 选择器非法），要写 `[id="123_456_0"]`。
- 【通用】同一站点不同岗位、不同年份的模板 `id` 可能变化，定位时以当前页面读到的为准。

## 六、保存与校验

- 【通用】成功判据是成功提示或保存接口的返回码，不是"点过按钮"。
- 【通用】分条目栏目的新增条目，字段 `id` 会带新序号，并且有的站点每个新增条目有自己的保存按钮。
- 【通用】报"某项未填写"时，先定位报错字段，逐个补齐再存一次；这一步不要整页重载——没保存的内容会直接丢。
- 【通用】长度限制有的按字符算，有的按字节算（一个汉字 2 字节），按更保守的口径裁。
- 【通用】起止时间必须成对填，缺一半会被校验拦下。

## 七、附件与上传

- 【通用】上传控件通常不能直接设值，要用通道提供的文件上传接口；没有的话只能请用户手工拖拽。
- 【通用】删除已上传的附件常是一个图标按钮，有的站点不弹确认、点了直接删。
- 【通用】有的站点有"上传简历文件后由系统自动解析并填充"的入口，那是整体导入、会替换页面上的简历内容，不要拿它当附件上传用。
- 【通用】上传前先确认简历文件夹里的附件文件存在且路径解析正确。

## 八、标签页生命周期

- 【通用】一个编辑会话对应一个标签页；不要在同一个账号下并行开两个编辑页。
- 【通用】保存成功之前不要刷新或重新加载：没保存的内容会直接丢。核对保存结果看成功提示或返回码，不要用刷新。
- 【通用】页面被系统回收或失效后，用同一个 URL 重开通常即可恢复（数据在服务端，登录态在浏览器配置里）。这是补救手段，不是常规做法。
- 【通道相关】需要保活接口的通道，每轮结束前调用它；忘了调用，下一回合用户会发现页面不见了。

## 九、失败排查顺序

1. 先读提示文本，不要凭猜测重试。
2. 定位报错字段的 `id`。
3. 判断是"确实没填"还是"框架状态没更新"——后者的信号是显示有值但校验不过。
4. 后者改用真实鼠标与键盘重填。
5. 连续失败两次以上就停下来，把现象、字段、提示文本报给用户，不要盲目重复点击。
6. 只有在确认当前内容已经全部保存、且不重新加载就没法继续时，才考虑重新加载页面；做之前先告诉用户。
