# 招聘表单填写

数据不在这个 skill 里。本 skill 只负责两件事：判断网页上的字段该取简历文件夹里的哪一条事实，以及按什么顺序、什么纪律把它填进去。具体值一律从简历文件夹读，不凭记忆或推测填写。

本文件只写与站点无关的规律，不沉淀某个具体站点的做法。下面每一条都按"有的站点会这样"的强度理解：到了具体页面上，以当场读到的为准，不要拿这里的描述当某个站点的既定事实。

## 硬规则

这几条的优先级高于下面所有流程细节。

1. **只用一个标签页、一个编辑会话**：不刷新、不新开标签页，也不为了"核对数据"另开一个简历页。有的招聘系统同一个账号只允许一个简历编辑会话，另开编辑页会让先打开的那个失效，之后所有保存都失败。
2. **填完不等于提交，全程只保存、不提交**。完成填写后的终态是"已保存"，不是"已投递"：不点「提交申请」「立即投递」「确认投递」这类把数据发给招聘方的按钮，也不点任何看起来会走完投递流程的下一步。是否提交、什么时候提交由用户自己决定。即使任务开头用户说过"填好就投出去"，真正点提交之前也要单独停下来再确认一次。
3. **必填项在同一轮填满**；成对的起止时间必须成对填完，只填一半会被校验拦下。
4. **一个子模块填完就保存一次**，不要攒到最后一起存。
5. **简历文件夹里没有的事，停下来问用户，不要编造。** `待补` 与 `〔不适用〕` 都不算已知值。
6. **简历文件夹只读**。发现缺漏或写错，记录下来、填完报告给用户，用户明确要求改时再改。
7. **临时产物**（截图、页面渲染图、导出文件）只写到当前工作区根目录下的 `.temp/`（目录不存在就创建），不写进简历文件夹，也不写进技能包目录。

## 简历文件夹在哪里

简历文件夹**固定**是工作区根目录下的 `generated-resume/`（名字固定，不做搜索、不改名）。工作区根目录就是当前工作目录；用户明确指定了别处时按用户的来。

它是**数据**，不在技能包目录（`job-form-filling/` 所在的那一层）里：技能包只放 skill 本身，不要往里写任何个人数据或临时产物。目录不存在时不要自己建、也不要另起一个名字：告诉用户先用 `resume-to-facts` 按模板生成它。

进入简历文件夹后，**先读根 `README.md`，再读每个要用到的类的 `README.md` 与 `模板.md`**。类 README 写的是这一类记什么、多个实例时怎么选、哪些填法靠语义猜不出来（某个下拉只能选特定值、某个字段在不同网站上要降级填、没有对应栏目时该项应改填到哪里）；类 `模板.md` 写的是这一类有哪些属性、每个属性是「必填」还是「可空缺」。完整结构契约见本目录的 `references/resume-folder-spec.md`。

读的时候注意三件事：

- 类 `模板.md` 标了每个属性是「必填」还是「可空缺」。**可空缺的属性整行没有，就是"没有这一项"，不要编造，也不要当成缺数据去追问。**
- 值是 `待补…` 或 `〔不适用〕…` 的都不能当已知值用；`〔不适用〕` 要连同原因一起理解，别把它填进表单。
- 根 `README.md` 的「已确认没有的项」记的是用户确认过"没有"的东西，填表时跳过即可。

## 模板在哪里

模板归 `resume-to-facts`，在它的技能目录下（`resume-to-facts/resumeTemplate/`），建库时才用得到。

本 skill 用不上模板——`generated-resume/` 的每个类目录里已经带着同一份 `README.md`（这一类记什么、注意事项与降级策略）和 `模板.md`（这一类有哪些属性、每条算不算必填、取值有哪些），读 `generated-resume/` 里的那份即可。简历文件夹是**只读**的：不往里面写个人数据或临时产物，也不改契约。

## 能力探测

动手前先看清当前环境能怎么操作浏览器，再选通道：

- **有浏览器自动化能力** → 用它，控件细节按 `references/browser-techniques.md` 处理。
- **只能注入 DOM 脚本** → 注意"显示有值但校验不过"的假成功，见 `references/browser-techniques.md`。
- **完全没有浏览器能力** → 降级：产出「字段 → 填什么」的清单，逐字段给出可直接复制的值，由用户手工填。

同一份任务里不要中途换通道。登录与短信验证码由用户本人完成，可以请用户先登录好，再从已登录状态接手。

## 流程

1. **读简历文件夹**：根 README，加目标站点要用到的类 README 与 `模板.md`。
2. **盘点字段**：把表单上每个字段的标签、是否必填、字数或字节上限、格式要求列成清单。
3. **生成答案表**：逐字段确定「取哪一类、哪个实例、哪一版」，形成对照表；字数受限时选不超过限制的最完整版本。通用映射方法见 `references/field-mapping.md`。
4. **交用户确认**：答案表给用户过目，这一步不要跳过。
5. **按模块填写**：写完一个信息集就保存一次，不要跨模块攒着一起存。
6. **逐模块回读核对**：每次保存后把页面上的值读回来和答案表比对；全部写完后再整体核对一遍。
7. **停在保存态**：全部写完并核对完之后，确认所有内容都已保存，就此结束，不做提交或投递。
8. **报告差异**：把没能填的、填了权宜值的、和简历文件夹对不上的，一并报给用户。

## 通用现象与对策

### 会话与标签页

- 有的系统同一个账号只允许一个简历编辑会话，再打开一个会让先打开的那个失效，此后所有保存都会失败（页面上的内容还在，但已经存不进去了）。全程只用一个标签页。
- 判断保存是否成功，看页面的成功提示或保存接口的返回码，不要靠重新加载页面来确认。
- 保存成功之前不要刷新或重新加载：没保存的内容会直接丢。
- 页面被系统回收或失效后，用同一个 URL 重开通常即可恢复（数据在服务端，登录态在浏览器配置里）。这是补救手段，不是常规做法。

### 输入与控件

- 优先真实鼠标点击加真实键盘输入。直接改控件的 `value` 再派发 `input`/`change`，在一些前端框架渲染的站点上会表现为：页面显示是对的，但框架状态没更新，点保存时报"某字段未填写"。判断信号就是**显示有值但校验不过**，遇到就改用真实键盘重填。
- 两级联动的下拉（省/市、门类/专业等）：先选父级，等子级选项加载完再选子级；父级没选时子级常显示"暂无数据"。
- 下拉要**点开弹层后再点候选项**，不要只改 `select` 的值。可搜索的联动框（学校、专业）：点开、输入关键词、等列表出现、再点中完全匹配的那一项；列表里通常还有"使用「某某」作为我的学校"这类自定义项，按用户的实际选择决定用不用。
- 候选项会随输入变化，点之前先取一次候选列表文本核对，不要凭上一次的坐标点。
- 日期控件常是只读的：先去掉只读属性，再输入 `YYYY-MM-DD` 并回车，最后读一遍值确认。有的站点把年月拆成两个下拉、真值存在隐藏输入里，两个都要写。
- 有的站点只能存到月份精度（`YYYY/MM`）。能填完整就填完整，只能存到月份的要在报告里说明。
- 复选框、单选框要点它的 label 或控件本身，不要只改 `checked`。

### 定位字段

- 优先用稳定的业务标识（`name`、`id`、label 文本），不要用位置索引和绝对路径选择器。
- 有的站点把字段 `id` 拼成"区块-字段-条目序号"这样一串用下划线连接的标识，可据此精确定位；同一站点不同岗位、不同年份的模板 `id` 也可能变化，以当前页面读到的为准。
- `id` 以数字开头时，不能直接写成 `#123_456_0`（CSS 选择器非法），要写成 `[id="123_456_0"]`。

### 校验与限制

- 长度限制有的按字符算，有的按字节算（一个汉字按 2 字节）。两个口径都估一遍，超限提示大意是"某某超出长度限制"，按更保守的那个口径裁。
- 分条目的栏目（教育经历、实习经历、获奖情况、家庭情况等）：点「添加新的某某」后，新条目会生成一整套带新序号的字段；有的站点每个新增条目有自己独立的「保存」按钮，填完必须点它那一个，只点全局的「保存」新增条目可能不落库。
- 保存后报"某项未填写"：先定位报错字段，逐个补齐再存一次；这时不要整页重新加载。
- 部分字段被禁用或只读，常见于由证件号码等推导出来的字段（性别、出生日期一类）。这类字段不要硬填，先保存一次让系统自己带出来，再回读确认。
- 简历文件夹里写"至今"的条目不填结束时间通常会被拦；网站没有"至今"选项时填当月，并在报告里说明这是权宜填法。
- 保存失败不要反复重点，先按提示定位原因再动手。

### 附件与上传

- 有的简历网站提供"上传简历文件、由系统自动解析并填充"的入口。这类入口是**整体导入**：上传后往往会替换掉页面上已有的简历内容（有的会先弹一个"将替换现有内容"的确认）。要传附件时不要走这个入口，走表单里的附件或证明材料上传控件。
- 替换已上传的附件：先删掉原来那个（有的站点删除不弹确认、点了直接删），再重新上传。
- 有的站点要求先勾选隐私政策或同意条款才能保存；这类勾选在页面重新加载后会被重置，保存前检查一遍。
- 上传文件前先说明传哪个文件、传到哪个字段，并取得确认。

## 不要做的事

- 不刷新页面、不新开标签页、不用第二个页面核对数据。
- 不点提交或投递类的按钮：填完就停在保存态，把是否提交留给用户。
- 不碰用户自己浏览器里开着的同一个简历编辑页：两边各开一个编辑页时，任一边保存都会覆盖整栏。发现用户也在那边改，提醒他只查看、不要在那边保存。
- 不在简历文件夹里留任何临时产物。

## 通用性

- 换浏览器操作通道、换招聘站点都不需要改这个 skill：通道按「能力探测」现场选，站点差异按「通用现象与对策」现场判断。
- 这里只写通用规律，不记录具体站点的做法。碰到本文没覆盖的现象，按当场从页面上读到的信息判断，并在报告里说明；确认是通用规律、而不是某个站点的一次性现象时，才回来补充本文。
